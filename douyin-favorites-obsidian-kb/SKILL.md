# Obsidian 个人知识库

核心工作流：定时读取授权抖音收藏 → 视频转写/图文 OCR → AI 总结分类 → 同步 Obsidian。新增与历史补录分开，已完成来源去重。此审核稿没有内置平台采集适配器，不得向用户声称安装后即可自动抓取。

目标是长期可检索、可追溯的个人知识库。Obsidian 中的 Markdown 是用户拥有的资料，不是模型的永久记忆。回答时实际检索授权库，并引用具体笔记及原资料位置。

## 先确认模式

- **整理资料**：用户指定文件或已授权收藏。读取 [内容规范](references/notes.md)，先取得原稿、图片文字或书籍章节，再整理知识笔记。不能只从标题猜内容。
- **新增同步**：读取 [同步与部署](references/sync.md)。第一次先记录完整的收藏 ID 基线，不处理旧收藏；以后只处理新 ID，以及已排队但未成功的项目。历史补录是独立模式，用户暂停历史补录不意味着关闭新增同步。
- **历史补录**：按用户指定的发布日期筛选，在下载前完成筛选。默认没有固定年份；配置的日期包含当天，使用配置时区。无法确认日期的资料跳过并报告。
- **书籍**：按章节整理，保留页码、章节和版本。将作者观点、解释补充与用户思考分开。扫描件需要 OCR；不能把尚未读取的章节写成已读。
- **知识库问答**：只检索指定库；回答区分库内证据、整理补充和未证实内容。跨库链接标明库名，不能假设 Obsidian 原生链接可跨库跳转。

## 执行与交付

技能内的 `scripts/kb.py` 提供本地基线、去重账本、笔记写入、分类入口和检索，使用 Python 标准库。它不会自行登录抖音或 TikTok、转写视频或调用云模型。来源采集与 AI 整理由宿主代理或用户单独安装的外部适配器完成，接口见 [输入契约](references/input.md)。只读取需要的参考文件。

1. 复制 `config.example.json` 为本地配置，填写授权库、状态目录和可选适配器。不要写入或发布密码、Cookie、Token、账号资料。
2. 宿主代理整理每个来源，产出符合契约的 JSON。笔记正文应去掉口头禅、重复和宣传，保留实质细节、依据、方法与必要限制。
3. 用 `kb.py import --mode new --input ...` 写入新增资料；用户明确要求旧资料时才用 `--mode backfill`。原始稿与图片保留本地，不进入发布仓库。
4. 脚本按来源 ID 去重，每条成功后更新分类导航。已删除的笔记记为 suppressed，不自动重建；重新导入需要用户明确决定。失败不标记成功。
5. 每日任务只运行 `sync` 新增模式。未建立完整基线时禁止启用；不在用户暂停历史补录后继续扫描旧内容生成笔记。

## 下载和资源边界

只采集自己的授权收藏。登录和验证码交给用户，不绕过访问控制。403 不等于视频已删除：从已登录页面刷新媒体地址后最多再试一次；仍失败则记录标题、ID、链接和阶段，停止盲目重试。同一原因连续五条失败时暂停批次。

浏览器只监听收藏或目标详情接口，过滤响应后再创建解析任务；扫描时阻止媒体自动播放，使用短生命周期会话。媒体和 OCR 串行或限制并发，转写模型复用或子进程隔离；内存不足时关闭浏览器并停止，不把后台 CPU 心跳当作进度。新环境不承诺既有错误已解决。

成功保存并校验笔记后再清理临时视频。图片和原稿是长期资产；失败的临时文件由保留策略管理，不能无限累积。报告区分扫描数量、符合条件的唯一 ID 数、尝试次数、成功数与失败数。未到列表末尾不能声称知道总数。

## 发布

仅发布技能自身代码与说明。第三方采集器、模型、浏览器、个人库及登录目录都不是发布内容。检查依赖许可证；本仓库不附带或改写受限上游代码。发布前验证配置脱敏和测试，说明已验证范围，不声称端到端采集已验证。
